## Local speech follow-up (2026-09-27, review branch only)

A separate browser-native adapter now probes `SpeechRecognition.available({ processLocally: true })` for the visitor's browser language and requires an installed pack before enabling Speak. Pack installation is an explicit settings action. Synthesis filters `speechSynthesis.getVoices()` to `localService === true` for the selected locale; recognition and synthesis are independent. Final recognized text enters the same Ayla Chat/IndexedDB text timeline, while New, typed turns, navigation, drawer close and interruption cancel active speech. No audio is persisted or silently sent to a browser speech provider. The voice settings expose an optional language/voice override rather than a fixed locale list.

Local Chrome preview on this machine reported the `en-US` recognition pack as **downloadable, not installed**, and no matching local synthesis voice; the microphone therefore remained disabled. This is a real browser capability observation, **not a successful local speech conversation**. The own-server multilingual speech fallback and explicit Cartesia option are separate gateway/UI integration work; public voice acceptance still requires a real end-to-end microphone→transcript→shared answer→audio/interrupt test. The current source, preview and tests must not be used to claim that the final spoken experience is live. Focused browser-adapter tests passed (3/3); the full frontend suite passed 105/105, Svelte check 0/0, Biome, static build and 238-page/5,825-link check passed. These tests use simulated speech APIs and do not establish real microphone/audio behavior.

## Owned-server speech follow-up (2026-09-27, review branch only)

A capability-gated client adapter is staged for the Aylith-owned voice gateway. It only enables server microphone capture when the live gateway reports ready STT; TTS readiness is independent, so a missing same-language voice leaves the answer as text without a silent English/Cartesia switch. Each turn carries a bounded slice of the same visible text conversation. Final transcript and answer text join that timeline; validated structured actions can open project content without cutting off the current spoken answer. New, manual navigation, drawer exit and explicit Stop interrupt the audio/turn. The adapter caps 16 kHz PCM bytes at the reported 30-second ceiling and isolates asynchronous resources by turn. This source work is **not proof of deployed models or real audio**: the owned runtime remained profile-off when staged, and actual microphone/Whisper/LLM/Piper playback, interruption/recovery and multilingual canaries remain release gates.

At local commits `6004278` and `3f58fd7`, the new shell also validates explicit `open_experience` actions for Classic, Explore or Ayla. It advertises the separate `experienceNavigation` capability alongside project navigation on HTTP and owned microphone turns; legacy clients do not opt in. An isolated headless Chromium run at actual 320×568, 390×568 and 848×568 captured Light/Dark idle and Voice-open views. The first true 320px capture exposed left clipping and a half-width Explore drawer; responsive toolbar wrapping and an absolute full-width drawer corrected both.
